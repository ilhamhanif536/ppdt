Majmu' Digital — Alur & Cara Kerja

Penjelasan visual tanpa istilah teknis yang rumit: bagaimana bagian Majmu' pada website Pondok Pesantren Darut Thalibin Telang disusun, dari pengunjung membuka halaman hingga teks bacaan muncul di layar — tanpa fitur audio agar tetap ringan.

Inti satu kalimat: Majmu' Digital adalah halaman tambahan di website pondok yang menampilkan bacaan rutin — tanpa server khusus, tanpa biaya API, dan tetap bisa dibuka kembali meski internet mati, karena teksnya tersimpan otomatis di perangkat pengunjung.
1

Tiga prinsip dasar

Keputusan teknis apa pun mengacu pada tiga prinsip ini.

🧩

Menyatu dengan website yang ada

Bukan aplikasi terpisah. Majmu' cukup menjadi alamat /majmu/ di repo ppdt, memakai tema hijau, sistem build, dan deploy Netlify yang sama. Tidak ada teknologi baru yang harus dipelihara pengurus.

📚

Memakai sumber data terbuka

Teks Al-Qur'an diambil dari EQuran.id (data Kemenag RI, gratis tanpa API key). Tahlil memakai dataset berlisensi MIT yang boleh dipakai ulang, dengan kredit sumber dicantumkan di setiap halaman.

📴

Ringan & ramah offline

Sekali surah dibuka, teksnya tersimpan di perangkat. Kunjungan berikutnya langsung terbuka tanpa internet — penting karena koneksi di lingkungan pondok tidak selalu stabil.

Perhatikan alurnya: browser pengunjung memanggil EQuran.id langsung, bukan melalui server pondok. Itu sebabnya website tetap berupa file statis biasa — tidak ada backend, database, atau tagihan server yang harus dikelola. Sebagai gantinya, setiap pengunjung menyimpan hasil unduhannya sendiri di perangkatnya.
3

Inti cara kerja: dua jalur data

Inilah yang membedakan Majmu' ini dari sekadar menautkan website orang lain.

Jalur A — Surah Pilihan Hybrid: API + cache
  1. Pengunjung membuka /majmu/baca/?surah=36 (Yasin).
  2. Browser memeriksa penyimpanan lokal.
    Jika sudah pernah dibuka: teks langsung dirender dari salinan tersimpan — cepat, dan tetap jalan saat internet mati. Muncul catatan "membaca salinan tersimpan".
    Jika kunjungan pertama: tampil status memuat, lalu browser mengunduh dari equran.id/api/v2/surat/36, membuang field audio agar salinan ringan, menyimpan sisanya, baru menampilkan.
  3. Tombol "Segarkan" memaksa ambil ulang teks terbaru dari API, menimpa cache lama.
  4. Jika unduhan gagal: ada cache → pakai cache; tidak ada cache → tampil halaman kesalahan dengan tombol "Coba lagi".
Jalur B — Tahlil, Dzikir, Dhuha Data milik sendiri
  1. Berkas JSON sudah ikut dibangun ke dalam website pada folder /data/majmu/ dan dihosting di domain pondok sendiri.
  2. Saat halaman dibuka, browser mengambil berkas kecil ini (total ±64 KB untuk tiga berkas) dari website pondok, lalu merendernya.
  3. Tidak bergantung layanan luar saat dibaca — hanya bergantung pada website pondok sendiri, dan browser biasanya meng-cache berkas ini secara otomatis.
  4. Cara memperbarui:
    Dzikir & Dhuha: jalankan npm run data:majmu — skrip menarik doa terbaru dari EQuran.id lalu menulis ulang JSON-nya.
    Tahlil: ganti isi tahlil.json, lalu build ulang.
  5. Hasil perubahan baru online setelah di-push dan Netlify membangun ulang — alurnya sama dengan mengubah halaman website biasa.

Struktur berkas di repo ppdt

Yang diwarnai emas adalah berkas baru khusus Majmu'. Sisanya sistem website lama yang tidak diubah strukturnya.

ppdt/
├── src/
│   ├── majmu/
│   │   ├── index.html            # daftar isi (/majmu/)
│   │   └── baca/index.html       # pembaca generik (/majmu/baca/?surah|tahlil|dzikir|dhuha)
│   ├── assets/
│   │   ├── majmu.css          # gaya khusus majmu' (tema hijau yang sama)
│   │   └── majmu.js           # otak aplikasi: fetch, cache, render teks (tanpa audio)
│   ├── index.html                # beranda: tidak diubah
│   └── _data/site-data.mjs       # menu utama: ditambah item "Majmu'"
│   └── _includes/footer.html     # ditambah tautan Majmu'
├── public/
│   └── data/majmu/
│       ├── tahlil.json           # 44 bacaan (dataset MIT, sumber NU Online)
│       ├── dzikir-shalat.json    # 13 dzikir & doa (dari EQuran.id)
│       ├── dhuha.json            # niat, tata cara, doa Dhuha
│       └── SUMBER-DATA.md        # catatan atribusi & lisensi
├── scripts/
│   ├── build.mjs                 # dirakit ulang: ikut menyalin /data & fingerprint aset majmu'
│   └── fetch-majmu-data.mjs   # perintah "npm run data:majmu"
└── package.json                  # ditambah satu perintah saja
6

Alur build & deploy

Pengurus cukup mengedit dan mendorong perubahan — sisanya otomatis.

Tahap 1Edit kontenUbah HTML, data JSON, atau data pusat di komputer/CodeSpaces
Tahap 2Build lokal (opsional)npm run build memeriksa & merakit ke folder dist/
Tahap 3Push ke GitHubNetlify mendeteksi perubahan dan menjalankan build yang sama
Tahap 4Online otomatisbuild.mjs merakit halaman, memberi hash aset, menyalin data, memperbarui sitemap
Apa itu "fingerprint / hash aset"? Nama berkas CSS/JS dibuat seperti majmu.572c76f0.css — angka tengahnya berubah setiap isi berkas berubah. Dengan begitu browser tidak mungkin menampilkan versi lama yang nyangkut di cache. Pengurus tidak perlu memikirkan ini; mekanismenya berjalan sendiri di build.mjs.

Peta jalan: mana yang sudah jalan, mana yang menyusul

Sudah berfungsi (MVP)

  • Al-Kahfi, Yasin, Ar-Rahman, Al-Waqiah, Al-Mulk — Arab, Latin, terjemah (tanpa audio, fokus ringan)
  • Tahlil & doa arwah (44 bacaan)
  • Dzikir & doa seputar shalat (13 doa, termasuk doa setelah Dhuha)
  • Panduan shalat Dhuha: niat, tata cara, doa
  • Cache otomatis + kartu "Lanjutkan membaca"
  • Toggle tampilan, ukuran teks Arab, tombol bagikan
  • Item menu navigasi (desktop & menu garis tiga HP), tautan footer, sitemap, dan atribusi sumber

Menunggu tahap berikutnya

  • Ratib Al-Haddad — perlu transkripsi & tashih pengurus (kartu "dalam penyiapan" sudah terpasang)
  • Maulid Ad-Diba' — disiapkan per rawi beserta mahalul qiyam
  • PWA + service worker: seluruh teks offline sejak kunjungan pertama (kini offline mulai kunjungan kedua)
  • Bagian Koperasi: profil, katalog produk, pemesanan via WhatsApp
8

Alur khusus Ratib & Diba': mengapa tidak langsung tayang

Teks ibadah berbeda dari teks API yang sudah terverifikasi — akurasi huruf dan harakat adalah keharusan, sehingga dibuat jalur pemeriksaan.

Langkah 1Naskah acuanPDF/cetak Ratib atau Diba' yang dipakai pondok ditetapkan sebagai rujukan
Langkah 2Transkripsi ke JSONDiketik terstruktur per bab/rawi, ditandai verified: false (draf)
Langkah 3Tashih pengurusUstadz/pengurus membandingkan dengan naskah acuan, memperbaiki, lalu menyetujui
Langkah 4TayangPenanda jadi verified: true, kartu di daftar isi diaktifkan, build & deploy
Selama proses berlangsung, dua kartu berlabel "Dalam penyiapan" sudah tampil di /majmu/ sehingga pengunjung tahu fiturnya sedang disiapkan — bukan rusak atau tertinggal.
9

Glosarium singkat

API

Pintu data di internet. Website memanggil alamat EQuran.id, dibalas data teks surah secara terstruktur — tanpa kunci/biaya.

JSON

Format berkas teks yang rapi untuk dibaca mesin — dipakai untuk tahlil, dzikir, dan dhuha.

localStorage

Ruang kecil di browser pengunjung untuk menyimpan cache & preferensi. Tidak ada data yang dikirim ke server pondok.

Build

Proses merakit file sumber di src/ menjadi situs final di dist/ yang siap dihosting.

Fingerprint/hash

Nama acak berbasis isi berkas agar perubahan selalu langsung terlihat, tidak tertutup cache lama.

PWA

Tahap lanjutan: website yang bisa "diinstall" di HP dan menyimpan lebih banyak konten untuk dipakai penuh tanpa internet.
